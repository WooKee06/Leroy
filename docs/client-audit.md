# Аудит клиентской части Leroy

Дата: 07.11.2026  
Охват: `Leroy/src` (React 19 + TypeScript + MobX + SCSS Modules).  
Метод: чтение кода и маршрутов, без изменения функциональности.

---

## 1. Коротко

Клиент — это рабочее Telegram Mini App с полным покупательским путём «каталог → товар → корзина → оформление → заказ», кабинетом продавца и TON-оплатой.

**Что уже работает**
- Каталог, поиск, товары, магазины, избранное, корзина.
- Оформление заказа: выбор ПВЗ/постамата СДЭК + оплата TON.
- Заказы: список и детали.
- Профиль, настройки, адреса (CRUD через сервер), роли.
- Магазин продавца: создание магазина, добавление товаров, редактирование магазина.
- Telegram-авторизация, TON-кошелёк, светлая/тёмная тема, skeleton-загрузки.

**Что не готово к продакшену**
- «Мок-оплата» видна и выбирается в чекауте, при этом это дефолтный способ оплаты.
- Из способов доставки реально работает только СДЭК; Почта, 5Post, курьер и самовывоз помечены «скоро».
- Стоимость доставки считается на клиенте (350 ₽ / бесплатно от 5000 ₽), а не по тарифам перевозчика.
- Telegram Stars, карты, баланс — интерфейс есть, оплаты нет.
- Поиск не умеет фильтры по цене/рейтингу/категории, нет пагинации.
- Профиль и настройки содержат заглушки: «2 адреса», «3 подарка», способы оплаты, язык, поддержка.
- Нет админ-панели, уведомлений, чата поддержки, i18n, полноценной аналитики продавца.

## 3. Что реализовано

### 3.1. Платформа и инфраструктура
- React 19, TypeScript, Vite, MobX, SCSS Modules, React Router.
- Типизированный API-слой (`leroyApi`) и мапперы DTO → view-модели.
- Авторизация:
  - Telegram Mini App (`initData`);
  - Telegram Login Widget для веба;
  - dev-вход, включается только через `VITE_DEV_AUTH`.
- TON Connect:
  - подключение/отключение кошелька;
  - подпись proof и привязка;
  - баланс, копирование адреса;
  - создание платежа, ожидание подтверждения по блокчейну, отмена.
- Темизация: светлая/тёмная.
- Skeleton-состояния на всех основных экранах (показываются только при первой загрузке).
- Общие компоненты: layout, persistent header, bottom nav, bottom action bar, quick view товара, bottom-sheet'ы.
- Тесты: 8 файлов / 31 тест (unit + store-тесты).

### 3.2. Каталог и поиск
- Главная: hero с поиском, быстрые действия, карточка баланса, чипы Hot / New / Deals / За Stars, сетка товаров.
- Каталог: категории, промо-слайдер, товары, блок магазинов.
- Поиск:
  - debounce 300 мс;
  - запрос к `/search`;
  - сортировка «популярные / дешевле / дороже» на клиенте.
- Магазины:
  - популярные по числу заказов;
  - поиск по названию/описанию на клиенте;
  - фильтр по категории магазина.
- Карточка товара: избранное, быстрый просмотр, продавец, цена/старая цена, рейтинг.

### 3.3. Товар
- Галерея изображений (Swiper).
- Выбор цвета и размера из вариантов товара.
- Табы: описание, характеристики, отзывы.
- Отзывы: загрузка, средний рейтинг, создание отзыва.
- Кнопка «Поделиться» через `navigator.share`.
- Нижняя панель: количество + добавление в корзину.

### 3.4. Корзина
- Серверная корзина с оптимистичным обновлением.
- Группировка по продавцу.
- Изменение количества, удаление, очистка после заказа.
- Итоги: товары, доставка, сумма.

### 3.5. Оформление заказа
- Bottom-sheet.
- Выбор ПВЗ/постамата СДЭК через пикер (город → точка).
- Ручное поле адреса.
- Выбор способа доставки (визуально).
- Выбор оплаты: TON работает, остальное — «скоро».
- Экран подтверждения TON: сумма, адрес, memo, срок действия.
- Ожидание подтверждения в блокчейне, повторная проверка, отмена.
- Создание заказа, очистка корзины, экран успеха.

### 3.6. Заказы
- Список с табами: все / ожидают / в пути / получены.
- Детали: статус, дата, товары, сумма, адрес, способ доставки, продавцы.
- Переход к списку заказов из профиля.

### 3.7. Профиль, настройки, адреса
- Профиль: аватар, имя, username, статистика по заказам/избранному/товарам.
- Плитки заказов по статусам.
- Баланс (карточка с пополнением).
- Меню: избранное, адреса, оплата, баланс, подарки, настройки.
- Настройки:
  - тема;
  - роль;
  - TON-кошелёк;
  - адреса (с реальным количеством);
  - выход.
- Адреса:
  - список, добавление, редактирование, удаление;
  - выбор адреса по умолчанию;
  - добавление/редактирование через пикер СДЭК;
  - получатель и телефон;
  - сохранение кода ПВЗ в комментарии;
  - пункты «Дом / Работа / Другое» отключены с подписью «Скоро откроется».

### 3.8. Продавец
- Создание магазина: название, описание, логотип, обложка (загрузка файлов).
- Добавление товара: название, цена, категория, описание, галерея (загрузка файлов).
- Витрина «Мой магазин»: обложка, логотип, статистика, товары.
- Аналитика: заказы, товары, рейтинг.
- Редактирование магазина: название, описание, логотип/обложка.

### 3.9. Роли
- Переключение покупатель / продавец / админ.
- Для продавца появляется пункт «Мой магазин».
- Роль хранится на сервере, токен обновляется.

## 4. Что не реализовано или реализовано частично

### 4.1. Критично для продакшена (P0)

1. **Мок-оплата доступна пользователю.**
   - В чекауте есть выбираемый пункт «Мок-оплата».
   - `checkoutStore.paymentMethod` по умолчанию `"mock"`.
   - В продакшене это нужно скрыть/запретить, а дефолт сделать безопасным (TON или явный выбор).

2. **Нет боевых ключей СДЭК.**
   - В `LeroyServer/.env` стоят публичные тестовые ключи.
   - Без боевых ключей нельзя считать тарифы, создавать заказы СДЭК и получать трекинг.

3. **Стоимость доставки считается на клиенте.**
   - `subtotal > 5000 ? 0 : 350`.
   - Не учитывает город, вес, габариты, тариф перевозчика, ПВЗ/курьера.
   - Итоговая сумма заказа может не совпадать с реальной стоимостью доставки.

4. **Смешение статусов «доступно / скоро».**
   - В массивах чекаута поле `disabled: true` означает «доступно», `disabled: false` — «скоро».
   - Логика инвертирована и легко ломается при следующей правке.

### 4.2. Оформление заказа и оплата (P1)

- Нет выбора сохранённого адреса из списка — только ручной ввод или пикер.
- Нет выбора способа доставки кроме СДЭК: Почта России, 5Post, курьер, самовывоз — «скоро».
- Нет расчёта тарифа и срока доставки от перевозчика.
- Нет выбора даты/интервала доставки.
- Нет комментария к заказу.
- Нет промокодов, скидок, сертификатов.
- Нет оплаты картой / Telegram Stars / балансом.
- Telegram Stars: UI есть, но помечен «скоро», провайдер `telegram_stars` на бэкенде не включён в клиентский сценарий.
- Нет экрана управления способами оплаты.
- Пополнение баланса — имитация: `accountStore.topUp()` меняет число в памяти, платежа нет.
- Нет возвратов и отмены платежа из интерфейса.
- Нет статуса оплаты в деталях заказа.

### 4.3. Заказы и послепродажный сервис (P1)

- Нет отмены заказа.
- Нет повторного заказа.
- Нет трекинга посылки.
- Нет чата с продавцом.
- Нет обращения в поддержку.
- Нет оформления возврата.
- Нет уведомлений о смене статуса (push / сообщения Telegram-бота).
- Нет оценки заказа и повторного отзыва из заказа.

### 4.4. Каталог, поиск и витрины (P2)

- Каталог загружает только первые 20 товаров и 20 магазинов, пагинации нет.
- Поиск:
  - нет фильтров по цене, рейтингу, категории;
  - нет истории и подсказок;
  - нет пагинации / бесконечной прокрутки;
  - счётчик результатов с неверным склонением («1 результата»).
- Магазины:
  - поиск и фильтры только по уже загруженным 20 магазинам;
  - нет пагинации;
  - нет подписки на магазин.
- Избранное: только товары; избранных магазинов как отдельного списка нет.
- Блок «Популярные магазины» на главной закомментирован.
- Нет блока «Похожие товары» на странице товара.
- Характеристики товара захардкожены по категориям (`SPECS_BY_CATEGORY`), а не приходят из API.
- На странице товара остался английский текст `Based on N reviews`.
- Нет размерной сетки и подсказки по выбору размера.
- Нет отображения остатков: недоступные размеры не блокируются.
- Отзывы: нет фото, лайков, сортировки, редактирования, удаления и модерации.
- Нет страницы «Все отзывы» — только вкладка на карточке товара.

### 4.5. Профиль и настройки (P2)

- «Адреса доставки» в профиле: захардкожено `"2 адреса"` вместо реального количества.
- «Мои подарки»: `"3 подарка"`, отдельного экрана и логики нет.
- «Способы оплаты»: нет маршрута и обработчика.
- «Баланс»: пункт меню без маршрута; пополнение не настоящее.
- Настройки:
  - «Способы оплаты» — без обработчика;
  - «Язык» — без обработчика, язык не переключается;
  - «Поддержка» — без обработчика, чата нет.
- Нет удаления аккаунта, политики конфиденциальности, юридических экранов.
- Нет управления уведомлениями.

### 4.6. Продавец (P3)

- Нет редактирования товара.
- Нет удаления/архивации товара.
- Нет управления остатками и вариантами (размеры, цвета).
- Нет скидок и акций.
- Нет изменения галереи после создания.
- Нет списка заказов покупателей и смены статусов.
- Нет печати/скачивания этикеток и интеграции с СДЭК для отправлений.
- Нет полноценной аналитики: выручка, просмотры, конверсия, периоды, графики, топ товаров.
- «Активность» — заглушка.
- Нет финансов: выплаты, комиссия, история начислений.
- Нет настроек магазина: категории, контакты, график, доставка, верификация.
- Нет ответов на отзывы.
- `myStore` ищется через `stores(100)` и фильтр по `ownerId`; отдельного эндпоинта «мой магазин» нет — при >100 магазинах продавец может не найти свой.
- `StoreEditPage` принимает логотип и обложку только как URL, без загрузки файла (в отличие от создания магазина).
- Новый товар создаётся без остатков и вариантов — нужно проверить, можно ли его реально купить.

### 4.7. Админка и платформа (P3)

- Нет админ-панели: пользователи, магазины, товары, заказы, платежи, споры, промокоды, контент, аналитика.
- Нет модерации товаров и магазинов.
- Нет i18n: все строки захардкожены по-русски, есть вкрапления английского.
- Нет центра уведомлений и push.
- Нет аналитики продукта (события, воронки, ошибки).
- Нет PWA/офлайн-режима.
- Нет code splitting: основной бандл ~1.45 МБ, Vite предупреждает о размере.
- Нет E2E-тестов; есть только unit/store-тесты.
- Нет глобального error boundary и единой системы toast-уведомлений.

## 5. Риски и технический долг

| Риск | Где | Влияние |
|---|---|---|
| Мок-оплата по умолчанию | `checkoutStore.paymentMethod = "mock"` | Пользователь может «купить» без оплаты |
| Инвертированный `disabled` | `CheckoutSheet` | Ошибки при добавлении новых способов |
| Фиксированная доставка | `cartStore.delivery` | Расхождение суммы с реальным тарифом |
| Тестовые ключи СДЭК | `LeroyServer/.env` | Невозможно боевое оформление |
| Захардкоженные характеристики | `ProductPage.SPECS_BY_CATEGORY` | Неверные данные о товаре |
| «Based on N reviews» | `ProductPage` | Английский текст в русском UI |
| `"2 адреса"` / `"3 подарка"` | `ProfilePage` | Недостоверные данные |
| Фейковое пополнение баланса | `accountStore.topUp` | Баланс не сохраняется и не оплачивается |
| Только 20 товаров/магазинов | `catalogStore.load` | Каталог выглядит пустым |
| `stores(100)` для «моего магазина» | `leroyApi.myStore` | Магазин может не найтись |
| Логотип/обложка только URL | `StoreEditPage` | Нельзя загрузить файл |
| Большой бандл | `vite build` | Медленная первая загрузка в Telegram |
